# any — the embeddable `any` backend artifact

`any` is the versioned, per-platform artifact the **Any** desktop app
(`anyproto/any-ui`) embeds. CI builds it on tag (release) + nightly
(prerelease); the publish fires a `repository_dispatch` that notifies the
client repos (`any-ui` desktop, `anytype-swift`, `any-kotlin`) to kick their
own builds. Build it locally with `make any` (or `scripts/build-any.sh`).

## Tarball layout (`any-<version>-<os>-<arch>[-sandbox].tar.gz`)

- `any[.exe]` — the backend (built from `cmd/any` with `-tags fts,vector`,
  the full search index — `docs/13-index.md` § build tags). The binary is
  `any`; `any` is the _artifact_ name.
- `llamacpp/` — prebuilt llama.cpp shared libs for this `(os,arch)`
  (`fetch-llamacpp.sh`). `internal/indexer/embed_local.go` looks for them at
  `<dir-of-any-exe>/llamacpp` by default, or `$YZMA_LIB`.
- `manifest.json` — `{ version, os, arch, llamacpp_version, sha256: {path: hash} }`.
  Consumers verify every file against `sha256` before use. The darwin
  `-sandbox` variants add `"variant": "sandbox"`; it is absent elsewhere.

### The darwin `-sandbox` variants

`darwin-arm64-sandbox` / `darwin-x64-sandbox` are for consumers that run `any`
as an **App-Sandboxed or hardened-runtime helper** without the
`com.apple.security.cs.disable-library-validation` entitlement
(`anyproto/any-swift`, whose helper is pinned by a CI gate to exactly
`app-sandbox` + `inherit`). Under library validation the default darwin binary
panics **before `main`**: `jupiterrider/ffi` extracts an ad-hoc-signed
`libffi.8.dylib` into the user Caches dir at package init and `dlopen`s it, and
an unsigned dylib that appears after the host was signed can never validate.

The payload is otherwise **identical** to the plain darwin tarball — same
`any` + `llamacpp/` + `manifest.json`, full vector leg including the
in-process local embedder. The only difference is the libffi source: built with
`-tags fts,vector,ffi_no_embed` plus
`-ldflags -X github.com/jupiterrider/ffi.filename=/usr/lib/libffi.dylib`, so
ffi loads Apple's shared-cache libffi (a platform binary, always valid) and
never writes to Caches (`docs/13-index.md` § build tags). The consumer re-signs
the bundled `llamacpp/` dylibs with its own team ID like any other embedded
library — that path was never the problem.

A two-sided post-build guard in `build-any.sh` fails the build unless the
binary has lost the embedded-libffi cache path **and** gained the `/usr/lib`
one; the second half matters because `-X` against a renamed upstream symbol is
silently ignored by the linker.

The plain darwin tarballs are unchanged — they stay any-ui's sidecar, which
carries the entitlement and signs the sidecar itself.

**The fork is meant to be temporary.** The sandbox flags are the strictly more
conservative macOS behavior, so the end state is one darwin build using them —
which is also what would let any-ui drop `disable-library-validation`. Two
things gate collapsing it: any-swift's in-sandbox verification passing, and a
`/usr/lib/libffi.dylib` symbol probe on the oldest supported macOS for both
arm64 and x86_64 (it is a shared-cache-only library with no SDK header, and
`ffi_get_struct_offsets` needs libffi ≥ 3.3). Until both hold, betting any-ui's
users on it is not justified.

The default embedding model (`Qwen3-Embedding-0.6B-Q8_0.gguf`) is **not**
bundled — it downloads at runtime into `<data-dir>/index/models/`.

## Platforms

Published: `darwin-arm64`, `darwin-x64`, `linux-x86_64`, `windows-x86_64`, plus
the two sandbox variants `darwin-arm64-sandbox`, `darwin-x64-sandbox` (above).
The backend is CGO-free (purego `dlopen`), so one Linux job cross-builds every
target and cross-fetches each platform's libs. (The bao agent no longer
ships in this tarball — it is the anybao runtime, embedded by consumers
such as any-ui.)

## Required CI secret

`ANY_CI_TOKEN` — a classic repo PAT with read+write across the `anyproto`
org. It does two jobs: (1) every build job fetches the private Go modules
(`any-sync-sdk`, …) with it via the `go-private-auth` action, and (2) the
`publish` job fires the `repository_dispatch` to the client repos (`any-ui`,
`anytype-swift`, `any-kotlin`). Store it in this repo's Actions secrets
(`gh secret set ANY_CI_TOKEN --repo anyproto/any`). The built-in
`GITHUB_TOKEN` can neither read other private `anyproto` repos nor dispatch
across repos, hence a dedicated token. Without it a build fails at module
fetch; the client dispatch is best-effort, so a missing/failed dispatch
warns but never fails the already-published release.

## PR checks

`pr-checks.yml` runs on every pull request:

- **swagger drift** — regenerates the OpenAPI spec (`make swagger`) and
  fails if `internal/server/docs` differs from what's committed. The spec
  is a published contract (anybao's `anyrt drift` pins against it), so a
  handler change whose annotations aren't reflected in a committed regen
  is a red PR. Fix: `make swagger`, commit the diff (`make build` runs
  the regen too). Note the spec captures routes, shapes, and status
  codes — not the `error.code` strings from `docs/06-errors.md`; a
  code-only change (e.g. renaming which code a 404 carries) is invisible
  to it and must be caught in review via `docs/06-errors.md`.
- **go vet** over the whole module.

Uses `ANY_CI_TOKEN` (above) for the private-module fetch, so it runs on
same-repo branches, not forks.
